Implementation, inspectable code, and honest limits for three selected projects. These notes point to repositories and a live product; they do not imply production usage where none is shown.

01 / BROWSER PRODUCT

Inkline

Open a PDF, draw and place a signature, then export the document in the browser.

IMPLEMENTATION

PDF.js renders pages to canvas; pdf-lib embeds signatures in PDF page coordinates. Placement survives viewport resizing.

ENGINEERING CHOICE

Files stay in the browser tab. The production Content Security Policy uses connect-src 'none' to block script-initiated network requests.

PROOF & LIMITS

The live app demonstrates the import-to-export flow and the architecture notes explain it. Rotated and encrypted PDFs are outside the supported scope.

02 / FULL-STACK APPLICATION

Agent Skills Manager

Create, manage, and publicly share Markdown-based agent skills.

IMPLEMENTATION

Next.js pages and routes handle skill creation, editing, account management, and public display; Prisma persists data in PostgreSQL.

ENGINEERING CHOICE

The repository documents bcrypt password hashing, httpOnly-cookie authentication, and ISR for the public skills gallery.

PROOF & LIMITS

The app directory, data model, and README are inspectable. No independently verifiable usage or performance metrics are claimed here.

03 / BACKEND SYSTEM

PatientFlow Cloud

A Spring Boot microservices project spanning patient records, billing, analytics, and authentication.

IMPLEMENTATION

An API gateway routes requests and validates JWTs; patient and billing services use gRPC, while analytics consumes Kafka events.

ENGINEERING CHOICE

The repository separates services and includes Docker and AWS infrastructure configuration. Synchronous calls and asynchronous events serve different workflow needs.

PROOF & LIMITS

Service modules and an integration-test directory are inspectable. Public materials do not independently establish production traffic, uptime, or throughput.
